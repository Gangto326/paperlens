# 해설 표본 검토

COMMIT_PLAN R4.7, PLAN 12.3. 사람이 해설을 읽고 판정을 적는 절차다. 자동 테스트는 해설이 실제로 이해되는지 재지 못한다.

코드: `src/main/eval/explanation-review.ts`. 실행: `npm run eval:review`. LLM을 부르지 않는다. 한도를 쓰지 않는다.

## 언제 하는가

2026-09-29 사용자 결정: 시트를 만드는 도구만 지금 만든다. 검토는 M5에서 한다.

같은 날 조사 지침을 고쳤고(`docs/quality-backlog.md` Q7), 문장 해설의 칸 구성도 바꾸기로 했다(Q9). 새 지침으로 조사를 다시 돌리면 개념 카드와 해설이 바뀐다. 지금 세대를 검토한 결과는 새 세대에 맞지 않는다. 그래서 검토는 M5에서 Q6과 Q7의 지침으로 다시 만든 세대에 한 번만 한다.

## 통과 기준

| 항목 | 기준 | 출처 |
|---|---|---|
| 초보자 해설 | 표본 30개를 모두 판정하고, 80% 이상(24개 이상)에서 다른 곳을 검색하지 않고 핵심을 이해 | PLAN 12.3 |
| 출처 무결성 | 검색 기록에 없는 출처 0 | 앱이 저장할 때 확인한다(`source-check.ts`). 사람이 세지 않는다 |
| 근거 적합성 | 표본의 주장과 출처를 대조. 직접 뒷받침하지 않으면 문제 항목 6으로 적는다 | PLAN 12.3 |

기준에 맞추려고 판정을 느슨하게 하지 않는다. 미달이면 미달로 적고 원인을 본다.

## 체크리스트

시트의 "문제 항목"에 적는 번호다. PLAN 12.3의 해설 검토 체크리스트와 같다.

1. 논문이 말한 사실과 일반적인 배경 설명을 구분했는가
2. 독자가 모를 약어를 다른 약어로 설명하지 않았는가
3. 비유가 조건·범위를 왜곡하지 않았는가
4. 해당 문장을 이해하는 데 필요한 정도의 길이인가
5. 수식이 가려진 부분을 아는 것처럼 설명하지 않았는가
6. 출처를 열었는가뿐 아니라 그 안에 주장에 대한 근거가 실제 있는가
7. 조사에 실패한 개념은 확인 불가로 남겼는가

## 절차

### 1. 시트 만들기

```bash
PAPERLENS_EVAL_CACHE="$HOME/Library/Application Support/paperlens/cache" \
PAPERLENS_EVAL_PDF_SHA=<sha256> \
PAPERLENS_REVIEW_OUT=<폴더> \
npm run eval:review
```

- `<폴더>`에 `review-sheet.md`(적는 곳)와 `sample.json`(표본 자료)이 생긴다.
- `review-sheet.md`가 이미 있으면 덮어쓰지 않고 실패한다. 적어 둔 판정을 지키려는 것이다. 새로 만들려면 다른 폴더를 주거나 파일을 옮긴다.
- 논문의 현재 세대를 읽는다. 세대 id가 시트 머리에 적힌다.
- `PAPERLENS_REVIEW_SIZE`(기본 30)와 `PAPERLENS_REVIEW_SEED`로 크기와 씨앗을 바꾼다.

### 2. 읽고 적기

표본마다 원문, 번역, 해설 칸, 개념 카드, 자료 링크가 있다. 앱 화면과 같은 내용이다. 끝에 세 줄이 있다.

```
- 판정:
- 문제 항목:
- 메모:
```

| 줄 | 적는 것 | 예 |
|---|---|---|
| 판정 | 다른 곳을 검색하지 않고 이 문장의 핵심을 이해했으면 `예`, 아니면 `아니오` | `- 판정: 예` |
| 문제 항목 | 체크리스트에서 걸린 번호. 없으면 비워 둔다 | `- 문제 항목: 2, 6` |
| 메모 | 자유롭게. 한 줄 | `- 메모: DPR을 풀어 쓰지 않음` |

- 판정은 필수다. 문제 항목과 메모는 걸리는 것이 있을 때만 적는다.
- 판정이 `예`여도 문제 항목을 적을 수 있다. 이해는 했지만 출처가 주장을 뒷받침하지 않는 경우가 그렇다.
- 항목 6은 링크를 열어 봐야 판단할 수 있다. 30개 모두 열지 않아도 된다. 연 것만 판단한다.
- 같은 개념 카드는 처음 나온 표본에만 전문이 있다. 뒤에서는 그 표본 번호를 가리킨다.

### 3. 세기

```bash
PAPERLENS_REVIEW_SHEET=<폴더>/review-sheet.md npm run eval:review
```

판정 수, 이해한 비율, 문제 항목별 수, 메모가 있는 표본을 출력한다. 모두 판정했고 비율이 80% 이상이면 통과다. 읽을 수 없는 줄이 있으면 통과가 아니다.

### 4. 기록

결과를 이 문서의 "검토 기록"에 적는다. 적은 시트는 커밋하지 않는다. 논문 본문이 들어 있다.

## 표본을 뽑는 방법

- 대상은 번역이 끝난 본문 문장이다.
- 섹션마다 문장 수에 비례해 몫을 나눈다. 짧은 섹션은 몫이 0일 수 있다.
- 섹션 안에서는 몫의 3분의 2를 개념 카드가 붙은 문장에서, 나머지를 카드 없는 문장에서 뽑는다.
- 순서는 씨앗과 문장 id의 해시로 정한다. 같은 씨앗이면 같은 문장이 나온다. 추출 결과가 같으면 세대가 달라도 같은 문장이 뽑힌다. 세대끼리 비교할 수 있다.

알려진 치우침: 몫이 1인 섹션에서는 카드가 붙은 문장이 뽑힌다. 2005.11401에서는 표본 30개 모두 카드가 붙은 문장이었다. 이 논문은 269문장 중 257문장에 카드가 붙어 있어 치우침이 작다. 카드가 적게 붙는 논문에서는 카드 없는 문장이 덜 뽑힌다.
